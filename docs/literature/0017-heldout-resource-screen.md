# 0017: bounded independent held-out resource screen

Checked 2026-10-19, approximately 20:08–20:13 UTC. This is resource reconnaissance, not an experiment or an admission to download. Only primary project pages, source text, a GitHub commit response, and HTTP HEAD responses were read. No dataset payload, archive directory, HDF5 value, image, model, or native estimator was accessed. ScanNet acquisition was excluded because the user's underlying dataset permission has not been established.

**Decision: no complete, verified, small calibrated relative-pose + monocular-depth cache was found that can presently be admitted as independent held-out data.** The strongest unresolved lead is RePoseD's ETH3D cache. An official link exists, but accessibility, size, scene inventory, and redistribution terms remain unverified. This bounded negative finding does not establish that no suitable cache exists.

The five 0017 landmark scenes remain development forever, including their unused pairs. MegaDepth0015 is development. Unread MegaDepth0022 is not established as unseen to the feature model. Independence must distinguish (a) different captured scenes, (b) untouched by our method development, and (c) absent from matcher/depth-model training. A distinct dataset name alone establishes none of the latter two.

Niantic source commit observed through the GitHub API: `c3290ec5fe992f816b6cf55686af7200ddd204dc`. The [extended-dataset instructions](https://github.com/nianticlabs/map-free-reloc/blob/c3290ec5fe992f816b6cf55686af7200ddd204dc/benchmark/extended_datasets.md) identify SIFT, SuperPoint/SuperGlue and LoFTR matches and PlaneRCNN depths for 7Scenes. This is a real author-provided resource, not a speculative cache.

**7Scenes has a calibration limitation beyond size.** Microsoft describes handheld Kinect capture, KinectFusion-derived camera-to-world poses, and separate train/test sequences, but explicitly says the RGB and depth cameras were not calibrated and their images are raw. Its quoted depth-camera defaults are focal lengths 585,585. Data is non-commercial under the linked Microsoft agreement. These indoor captures are a distinct source from our outdoor landmark scenes; matcher/depth-model training independence was not verified. [Microsoft dataset description and license](https://www.microsoft.com/en-us/research/project/rgb-d-dataset-7-scenes/).

The Niantic [7Scenes loader](https://github.com/nianticlabs/map-free-reloc/blob/c3290ec5fe992f816b6cf55686af7200ddd204dc/lib/datasets/sevenscenes.py) instead assumes RGB K with focal length 525 and principal point (320,240), then rescales K; reads pair quaternion/translation as the image-0-to-image-1 transform; and loads reference/query absolute labels separately. Its [depth utility](https://github.com/nianticlabs/map-free-reloc/blob/c3290ec5fe992f816b6cf55686af7200ddd204dc/lib/datasets/utils.py) divides stored depth by 1000. Reproducing this convention would reproduce a benchmark assumption, not prove calibrated RGB geometry. Niantic's [software license](https://github.com/nianticlabs/map-free-reloc/blob/c3290ec5fe992f816b6cf55686af7200ddd204dc/LICENSE) is a separate non-commercial license; it does not supersede Microsoft's data terms.

**Map-free has an appropriate pose contract, but no verified small complete cache.** Its [README](https://github.com/nianticlabs/map-free-reloc/blob/c3290ec5fe992f816b6cf55686af7200ddd204dc/README.md) specifies per-frame `fx fy cx cy width height`, world-to-camera metric poses, and validation queries relative to an identity reference pose. Test poses are withheld. The [official dataset page](https://nianticspatial.com/research/map-free/dataset) lists 8 GB validation, 15 GB test and a 0.5 GB three-scene sample; the sample is not a separately verified matching/depth cache. Dataset use is non-commercial under its own agreement. These are newly crowdsourced places, but overlap with our named landmarks and pretrained-model training was not checked, so source independence is plausible rather than certified.

## Most promising unresolved lead: RePoseD ETH3D

The [official RePoseD README](https://github.com/kocurvik/mdrp/blob/main/README.md#download-the-eval-dataset) links [extracted correspondences plus several monocular depth predictions](https://415102.xyz/api/public/dl/GpNgZVTQ) and explicitly gives `roma/eth3d` as an evaluation directory. One HEAD request returned **403 Forbidden**. No alternate endpoint, authenticated request, or payload request was attempted. Thus archive size, range structure, exact ETH3D scenes, compact per-scene files, and cache-specific license are unresolved. Do not claim this is already a usable cache or silently replace it with PoseBench's ETH3D absolute-pose data: [PoseBench's dataset table](https://github.com/vlarsson/PoseBench#datasets) distinguishes absolute pose from monodepth relative pose.

ETH3D source data uses [CC BY-NC-SA 4.0](https://www.eth3d.net/). ETH3D's [stereo documentation](https://eth3d.ethz.ch/documentation) describes authored calibration, but the RePoseD cache's exact producer/scene contract must be established before transferring those assumptions. The ETH3D SLAM collection is a different collection: its [documentation](https://eth3d.ethz.ch/slam_documentation) specifies undistorted pinhole images, `fx fy cx cy`, top-left pixel **center** at (0,0), camera-to-world timestamped poses, and active-stereo depth. Its [overview](https://eth3d.ethz.ch/slam_overview) separates mocap sequences from five SfM sequences. Active-stereo/laser depth is not a monocular prediction and must not become an estimator input in a monocular-depth experiment. No official small matches+MDE cache for ETH3D SLAM was verified.
