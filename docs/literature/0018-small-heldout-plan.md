## Map-free: verified bounded range route

The [official dataset page](https://nianticspatial.com/research/map-free/dataset) offers 65 validation places, each with one reference and a query scan plus poses. Its terms allow non-commercial research and personal experimentation. The test split lacks public poses. We use the official validation asset URL, not a mirror: `https://storage.googleapis.com/niantic-lon-static/research/map-free-reloc/dataset/val.zip`.

HEAD returned 200, length **7,907,389,876 bytes**, ETag `"efdc0e742961dbe955226543ad213d35"`. Four subsequent requests returned verified 206 ranges with the same ETag and exact Content-Range totals: EOCD 22 bytes, ZIP64 locator 20 bytes, ZIP64 EOCD 56 bytes, and central directory **3,945,700 bytes** at offset **7,903,444,078**. Actual body transfer was **3,945,798 bytes**, below the prospective 4 MiB cap. No member payload was requested. The directory has **37,195 entries**, all deflate, including **36,998 JPEGs**. There are exactly 65 scene IDs `s00460`–`s00524`; each has `seq0/frame_00000.jpg`, 243–581 `seq1` images, `intrinsics.txt`, `poses.txt`, and `poses_device.txt`.

Metadata alone gives a useful strict payload upper bound: any reference plus 16 queries and the complete intrinsic/pose text files costs at most **5,754,015 compressed bytes per scene**; taking the 17 largest JPEG entries separately in each scene gives **287,255,210 bytes for all 65 scenes**, before ZIP local-header/name/extra overhead. This is a resource bound, not a selected cohort. At least five distinct authored places can therefore be allocated prospectively without downloading the archive. All scene/frame allocation, including exclusion rules, remains future work and must precede numeric payload access. Shared-reference pairs within a scene are correlated; scene-level analysis is necessary.

Private receipts are in chat `work/0018-resource-screen/`: `mapfree-val-directory-receipt.json`, `mapfree-val-central-directory.bin`, `mapfree-val-members.json`, and the derived `mapfree-val-scene-inventory.json`. Directory SHA256 is `5c53ffaf13fcbcaf3c40d2d30a979ba104fe2cf4110237f667fac446e24782f9`; member-inventory SHA256 is `e5d205f57c7cc30224b260b644ffb62bbdd0f4c4a67b74d72b0e5337ae297dbb`. This is not a hash of the whole 7.9 GB archive. Future extraction must verify ETag, exact ranges, local ZIP headers, decoded member sizes and CRCs, and record local SHA256 values. Abort on ignored Range, changed archive identity, or access denial.

The [author README at c3290ec5fe992f816b6cf55686af7200ddd204dc](https://github.com/nianticlabs/map-free-reloc/blob/c3290ec5fe992f816b6cf55686af7200ddd204dc/README.md) supplies the format contract: per-frame `fx fy cx cy width height`, metric world-to-camera quaternion/translation, and validation queries relative to the reference. Actual values remain unread. RGB inference must preserve or explicitly transform camera coordinates, and labels must stay behind a complete prediction seal. Known calibration does not authorize using sensor or ground-truth depth as a monocular input.

The conservative transfer ledger retains the full 4 MiB reservation: **2,771,072,148 − 4,194,304 = 2,766,877,844 bytes** before future payloads. The directory request itself used 248,506 bytes less than that reservation. Source/API metadata transfers are distinct from this directory receipt. ## MoGe-2 pin and lightweight inference route

Do not install current MoGe main, which has moved to MoGe-3. The pre-V3 source parent is [925b8ed835a7a9cdb7578ba15c658a0afc969030](https://github.com/microsoft/MoGe/tree/925b8ed835a7a9cdb7578ba15c658a0afc969030). Its [packaging](https://github.com/microsoft/MoGe/blob/925b8ed835a7a9cdb7578ba15c658a0afc969030/pyproject.toml) is version 2.0.0, Python ≥3.9 and torch ≥2; it has no MoGe-3 Triton requirement. Code is MIT, with the included DINOv2 code separately Apache 2.0.

The official [Ruicheng/moge-2-vits-normal](https://huggingface.co/Ruicheng/moge-2-vits-normal) checkpoint is 35M parameters. Hugging Face metadata pins revision `26b477f41595707c5db6770294c0d1721e8ed4ed`, `model.pt` **140,550,416 bytes**, SHA256 `79a16621928c2bf0ed04659218c55c01075e950507f40bb3332fb4c873d3e1dc`; these are publisher LFS metadata, not our downloaded-file verification. [Pinned asset](https://huggingface.co/Ruicheng/moge-2-vits-normal/resolve/26b477f41595707c5db6770294c0d1721e8ed4ed/model.pt). The model card declares MIT but supplies little checkpoint-specific training detail.

Source inspection of [v2.py](https://github.com/microsoft/MoGe/blob/925b8ed835a7a9cdb7578ba15c658a0afc969030/moge/model/v2.py) and [modules.py](https://github.com/microsoft/MoGe/blob/925b8ed835a7a9cdb7578ba15c658a0afc969030/moge/model/modules.py) supports a CPU float32 route with native PyTorch SDPA. The backbone is constructed with `pretrained=False`, so loading the full checkpoint need not fetch a second DINO checkpoint. The optional initialization method would fetch one and must not be called. Full `.infer()` includes focal/shift recovery and metric-scale postprocessing; raw network outputs are not interchangeable. Its optional horizontal FOV is not a general full-K camera model. Estimation must retain authored calibration. `load_state_dict(..., strict=False)` means a later artificial qualification must explicitly inspect missing/unexpected keys rather than silently accepting incompatible weights.

Local package metadata reports torch 2.8.0, NumPy 2.0.2 and Pillow 11.3.0 already present; this was not a torch import or inference test. Compatible macOS ARM/Python 3.9 wheel metadata gives torchvision 0.23.0 **1,856,927 bytes**, SciPy 1.13.1 **30,324,538 bytes**, and OpenCV 4.11.0.86 **37,326,322 bytes**. Remaining helpers, including Hugging Face Hub and the pinned `utils3d`/`pipeline` source dependencies, still need a complete bounded lock. Avoid installing the broad CLI/UI package extras. CPU time and peak working memory under the 8 GiB limit remain unmeasured.

## Matching and training exposure

[LightGlue source eb42fee2d71449efb0aa5c10549752b5d75384d8](https://github.com/cvg/LightGlue/tree/eb42fee2d71449efb0aa5c10549752b5d75384d8) has a CPU route. Official release `v0.1_arxiv` metadata lists `superpoint_lightglue.pth` **47,500,279 bytes** and `superpoint_v1.pth` **5,206,086 bytes**; asset hashes must still be verified at acquisition. Its loaders automatically fetch weights, so any future qualification must supply local pinned assets and prohibit hidden downloads. LightGlue is Apache 2.0; SuperPoint carries its separate [Magic Leap license](https://github.com/magicleap/SuperPointPretrainedNetwork/blob/master/LICENSE). Classical SIFT with fixed mutual/ratio matching is a zero-weight alternative and a useful input control, but using weaker matches is not evidence of beating a strong learned-input baseline.

The pinned [MoGe-2 training config](https://github.com/microsoft/MoGe/blob/925b8ed835a7a9cdb7578ba15c658a0afc969030/configs/train/v2.json) lists 24 datasets, including MegaDepth, ScanNet++, ARKitScenes, Waymo and synthetic collections; it does not name Map-free, TUM RGB-D or ETH3D. The [MoGe-2 paper appendix](https://arxiv.org/html/2507.02546v1) describes that training mixture. This does **not** prove the small checkpoint or DINOv2 pretraining excludes those images. Report separately: new physical captures; untouched by our method development; and verified absent from upstream training. Only the first two can presently be planned for Map-free; pretrained-model exposure remains uncertain.

For TUM, HEAD verified `rgbd_dataset_freiburg3_long_office_household.tgz` at **1,483,556,251 bytes**. The [official formats/calibration](https://cvg.cit.tum.de/data/datasets/rgbd-dataset/file_formats) specify undistorted Freiburg3 images, whereas Freiburg1/2 require distortion handling. The [dataset page](https://cvg.cit.tum.de/data/datasets/rgbd-dataset) licenses data CC BY 4.0. One room's many sequences are not multiple independent physical scenes; no room-level multi-scene claim is admitted. The large TGZ also transfers unused sensor depth. This is a possible distinct indoor source only after a separate bounded allocation and inference qualification, not a reason to replace the cheaper verified Map-free route now.
