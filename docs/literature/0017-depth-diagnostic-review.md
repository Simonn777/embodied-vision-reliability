# 0017 review: a minimal known-depth baseline diagnostic

2026-10-19. Prospective design review only. No cache arrays, images, labels, or native estimator calls were accessed for this note. Source review used PoseLib `6a636b1d84273d5e3ba97676463476569611572a` (declared version `3.0.0`) and PoseBench `7b494256e89a13c47ab37b6917c2e0d3dae0c2e4`. The parent must register the actual protocol and bindings before execution.

**Recommendation:** one fixed-seed, four-arm comparison on 80 preallocated development pairs is a reasonable next information diagnostic. It tests whether supplied depth generates useful poses unavailable to geometric estimation, and what harm accompanies that benefit. It proposes no new estimator. The failed 0016 necessary headroom gate closes ordinal selection on its existing four-candidate bank; it does not establish anything about these different inputs.

## Allocation and observation boundary

Use only the five official `*_roma_moge.h5` bundles: `florence_cathedral`, `lincoln_memorial`, `london_bridge`, `milan_cathedral`, and `sagrada_familia`. Previously verified Content-Length totals **53,112,544 bytes**; exact URLs and per-file lengths are in `0016-monodepth-resources.md`. Acquire and hash the five files under a separate asset receipt. No image or model inference is required. These are author-labelled cached predictions, not verified checkpoint identities or an end-to-end front-end reproduction. The [pinned loader](https://github.com/PoseLib/posebench/blob/7b494256e89a13c47ab37b6917c2e0d3dae0c2e4/src/posebench/monodepth_relative_pose.py) defines the input fields and scene/matcher/depth combinations.

Inspect names/shapes only first. For each physical scene, sort pair keys by SHA256 of the UTF-8 string `evr0017:development:2026-10-19\0<scene>\0<pair-key>` and take the first 16; ties break lexicographically. Save all 80 identities, order, file hashes and the literal salt before reading values. If a scene has fewer than 16 pairs, stop and amend the design before numerical access; do not silently replace it. Treat **all five physical scenes as permanently development**, including unselected pairs. Repeated images within/across pairs are not independent replicates; record available identity metadata and do not claim independence from earlier MegaDepth work without an overlap audit.

Prediction workers may read only each selected pair's `x1`, `x2`, `K1`, `K2`, authored cameras and `depth1`, `depth2`. Pass identical ordered coordinates/cameras to every arm; pass the author depth fields unchanged to depth arms. The [consumer contract](./0016-monodepth-consumer-contract.md) establishes axial z-depth proxies with shifts in that domain, not unit-ray distances. Do not infer an alternative convention from outcome quality or repair negative/odd depths by an unregistered transform. Record input shape/finite/sign checks; no result-selected pair or point deletion.

All 320 arm outputs must reach a sealed terminal state, with input/source/library/options hashes, before a separate evaluator can read selected `R`/`t`. Timeout/native failure is an explicit unavailable outcome, not a replacement pair or a retry. Binding/input corruption blocks evaluation. Labels are unavailable to allocation, validity rules, solver calls and any derived selection.

## Four arms and exact setting translation

Use the already built current library pin, one fixed seed `0`, and the official bounded PoseBench RANSAC budget: `min_iterations=100`, `max_iterations=1000`, `success_prob=0.9999`. Explicitly retain `dyn_num_trials_mult=3`, no progressive sampling, and no initial-model scoring. Use native `bundle={}` and record its effective defaults from the source. Do not disable joint refinement or substitute the older RePoseD pipeline.

| Arm | API and explicit distinguishing options |
|---|---|
| E-normalized | `estimate_relative_pose`; **`max_error=2.0`**, `tangent_sampson=false`, `real_focal_check=false` |
| E-TS | Same API, **`max_error=2.0`**, `tangent_sampson=true`, `real_focal_check=false` |
| RePoseD-scale | `estimate_monodepth_relative_pose`; **`max_errors=[16.0,2.0]`**, `estimate_shift=false`, `weight_sampson=1.0` |
| RePoseD-affine | Same monodepth API; **`max_errors=[16.0,2.0]`**, `estimate_shift=true`, `weight_sampson=1.0` |

The plural depth option orders **reprojection, epipolar** thresholds. The ordinary E parser reads singular `max_error`; forwarding only plural `max_errors` would leave its default threshold unchanged. Nested `ransac`/`bundle` dictionaries are required. See the [pinned parsers](https://github.com/PoseLib/PoseLib/blob/6a636b1d84273d5e3ba97676463476569611572a/pybind/helpers.h#L108) and [PoseBench configuration](https://github.com/PoseLib/posebench/blob/7b494256e89a13c47ab37b6917c2e0d3dae0c2e4/src/posebench/monodepth_relative_pose.py#L95).

The monodepth wrapper converts image thresholds with `0.5*(1/focal1+1/focal2)`, retains depths, and uses reprojection scaling `(2/16)^2=1/64`. It performs final joint refinement on its returned epipolar inliers. Preserve the raw final depth geometry `(R,t,scale,shift1,shift2)`; normalizing `t` without rescaling the depth gauge would invalidate reprojection diagnostics. Pose-angle evaluation may separately normalize `t`. [Pinned wrapper](https://github.com/PoseLib/PoseLib/blob/6a636b1d84273d5e3ba97676463476569611572a/PoseLib/robust.cc#L383).

**Do not call this a guaranteed geometric fallback.** The pinned calibrated monodepth estimator generates P3P proposals in scale mode and three-point monodepth proposals in shift mode. It scores with normalized Sampson error and refines with depth plus Sampson residuals; its proposal function contains no five-point branch. This differs from describing every hybrid depth/geometry objective as retaining the point-only winner. [Proposal, scoring and LO source](https://github.com/PoseLib/PoseLib/blob/6a636b1d84273d5e3ba97676463476569611572a/PoseLib/robust/estimators/relative_pose.cc#L112), [RANSAC entry](https://github.com/PoseLib/PoseLib/blob/6a636b1d84273d5e3ba97676463476569611572a/PoseLib/robust/ransac.cc#L199).

One serial call per arm/pair gives 320 calls, not four seeds. Rotate the arm order by global pair index modulo four. Use one native thread, at most four CPU threads overall, 8 GiB working memory, a 30-minute cohort limit and a fixed per-call watchdog declared before execution. Keep all timeouts/failures. Equal iteration caps are not equal compute: report call wall time, initialization/loading time and total cost separately. Cached front-end inference is excluded and unavailable, so no end-to-end efficiency claim follows.

## What to retain and report

Before GT access, retain final poses and raw depth parameters, returned RANSAC stats/inlier masks labelled **pre-final-refinement**, statuses, timings and deterministic seed/options. Recompute common final-pose geometric scores at the explicit 2-pixel threshold, including cheirality and saturated degeneracies. Keep normalized and TS objectives distinct; neither is the other's exact pixel-noise equivalent off the epipolar manifold. A final geometric score cannot certify pose truth.

The Python return is `(geometry, info)`. `geometry` is a `MonoDepthTwoViewGeometry` exposing exactly `geometry.pose.R`, `geometry.pose.t`, `geometry.scale`, `geometry.shift1`, and `geometry.shift2`; `info['inliers']` is the returned mask. Store raw `pose.t`, its norm, and a separate normalized direction if desired. There is no permission to overwrite the raw gauge. [Binding fields](https://github.com/PoseLib/PoseLib/blob/6a636b1d84273d5e3ba97676463476569611572a/pybind/bindings/types.cc#L49), [return construction](https://github.com/PoseLib/PoseLib/blob/6a636b1d84273d5e3ba97676463476569611572a/pybind/bindings/estimators/relative_pose.cc#L54).

**Mask semantics matter.** `ransac_monodepth_relpose` obtains this mask by epipolar `get_inliers` after RANSAC/internal LO and before the wrapper's final refinement. When `stats.num_inliers>3`, the wrapper passes the points selected by that mask into final refinement. It does not recompute the returned mask afterward. The mask is thus the supplied support for that final call, not its final epipolar inlier classification, and not its state-dependent active directional depth support. Internal RANSAC LO calls the depth refiner on all supplied correspondences; a trace of those calls is not exposed in this API. The baseline cannot recover their intermediate states from `info`.

Using `h1=(u1,v1,1)`, `h2=(u2,v2,1)` and the **raw** output state, define `c1=d1+shift1`, `c2=d2+shift2`, `z2_corrected=scale*c2`, `Z12=R(c1*h1)+t`, and `Z21=R.T(z2_corrected*h2-t)`. Record separate counts of `c1<=0`, `c2<=0`, `z2_corrected<=0`, `Z12.z<=0`, `Z21.z<=0`, their union, and each direction's finite active count. Compute every count on **ALL fixed matches** and separately on `info['inliers']`; retain both denominators. Distinguish nonfinite arithmetic from finite nonpositive depth. These are diagnostics, not output rejection criteria. Preserve all finite native outputs even when nuisance parameters look unfavorable; never improve coverage by deleting cases.

After the baseline outputs are sealed, a separately specified read-only diagnostic can compute a full fixed-denominator reprojection reference. For a fixed set `S` (all matches or the sealed returned mask), let `ell12_i=min(1, ||project_camera2(Z12_i)-q_i||^2/16^2)` if `Z12_i.z>0` and its projection is finite; otherwise set `ell12_i=1`. Define `ell21` symmetrically, and `C_fixed(S)=sum_i(ell12_i+ell21_i)/(2*|S|)`. An empty mask is unavailable, not a zero score. Nonfinite projection arithmetic is counted explicitly. Camera projection must use the same authored cameras. **No invalid direction disappears from the denominator.** Negative source-corrected depth counts remain separate, since the native omission rule tests transformed depth. This capped pixel reference is not the native normalized Cauchy objective. The analogous capped omission score differs by exactly the omitted fraction; that arithmetic identity is not causal evidence of pose harm.

Use directed translation-angle and rotation-angle errors, and their maximum, as in [PoseBench's geometry utilities](https://github.com/PoseLib/posebench/blob/7b494256e89a13c47ab37b6917c2e0d3dae0c2e4/src/posebench/utils/geometry.py#L13). Publish AUC5/10/20 for every arm, every scene and all 80 pairs, with failures penalized at 180 degrees; show success-only metrics separately. Any GT rotation projection or validation policy must be frozen and disclosed. Report all per-pair errors, angle changes, failure categories and timings.

Predeclare the following descriptive comparisons:

- For each depth arm against **both** geometric arms: error difference, wins/ties/losses, and material benefit/harm counts. A useful fixed definition is a change of at least 1 degree or crossing the 5-degree success boundary; report raw differences as well. These thresholds describe outcomes and do not filter them.
- `O_G`: per-pair GT oracle minimum of the two geometric arms; `O_D`: minimum of the two depth arms; `O_ALL`: minimum of all four. Report `AUC5(O_ALL)-AUC5(O_G)` as additional candidate-generation headroom, and `AUC5(O_ALL)-max_m AUC5(m)` as four-arm complementarity. These are oracle diagnostics, never deployable results.
- Show reciprocal rescue and damage: geometric failure/depth success and geometric success/depth failure, plus rotation-versus-translation changes. A mean gain can conceal many damaged pairs.
- Summarize all five scenes and the leave-one-scene-out range descriptively. Five scene groups do not justify confident population generalization or treating 80 overlapping pairs as independent trials.

An optional no-extra-call control may select the smallest **recomputed common geometric score** among the four sealed final poses, with a fixed tie order. If included, register it in advance and report its selection errors against the oracle. Label it an external final-pose selection control; it is not the official RePoseD fallback. It still cannot guarantee non-harm in GT error.

## A conditional, specific follow-up question

There is one source-grounded mechanism worth measuring without changing the baseline: **state-dependent omission of depth reprojection terms during joint refinement**. The current calibrated refiner adds a forward depth residual only for `Z1.z>0` and a reverse residual only for `Z2.z>0`. Scale/shifts receive unconstrained additive updates in its `step` function. Thus a changed state can remove a residual rather than reduce its reprojection error. This is an implementation property; it has not been shown to occur or to harm these inputs. [Residual construction](https://github.com/PoseLib/PoseLib/blob/6a636b1d84273d5e3ba97676463476569611572a/PoseLib/robust/optim/monodepth_relpose.h#L133), [state update](https://github.com/PoseLib/PoseLib/blob/6a636b1d84273d5e3ba97676463476569611572a/PoseLib/robust/optim/monodepth_relpose.h#L297).

Register the advance condition before labels are opened: for the **same depth arm**, at least one pair in each of **at least two of the five scenes** must show material harm versus both geometric outputs (at least 1 degree worse than each, or depth error at least 5 degrees while both geometric errors are below 5), **and** at least one inactive transformed-depth direction on that arm's nonempty sealed returned mask. Report every pair and both arms, not just the qualifying examples. This is a minimal trigger for a mechanism audit, not statistical evidence, a fitted threshold, or a method success criterion. Useful depth candidate headroom must separately survive the declared admission gate if the aim is an accuracy method beyond the geometric baseline.

If that condition holds, the next falsifiable question is: *does joint refinement lower its implemented objective by losing active depth terms while moving away from a better pose?* Final counts alone cannot answer causally. A separate prospective audit would log a frozen initial state and each accepted native LO step, compare active-term counts, `C_fixed` and pose errors, and evaluate a matched-initialization control under an explicitly fixed visibility treatment. Keep exactly the same initial geometry, correspondences, nuisance parameterization, loss/thresholds and iteration budget. It must separate proposal failure from damage introduced during refinement; baseline final outputs alone cannot do so. No implementation or rerun of this follow-up is admitted here.

This audit may reveal an ordinary implementation defect. Standard cheirality constraints, penalties, fixed-support optimization or adaptive weighting are not automatically novel. Only a broader, identifiable error mechanism and an independently validated improvement beyond known controls could motivate further research; none is established here.

**Close or narrow the direction** if depth has negligible oracle generation headroom, if apparent benefit merely reproduces known affine calibration, if harm is confined to invalid inputs/timeouts, or if inactive-term counts do not support the proposed mechanism. Retaining the earlier 2-percentage-point oracle admission threshold is a reasonable prospective necessary gate for another four-output selector; it is not a success criterion for a new method. If depth improves all relevant cases cleanly, that is successful use of a known method, not evidence for a new weighting scheme. If depth and geometry fail together, their agreement does not validate either observation source.

The output of this diagnostic is a decision about whether there is a specific unresolved failure to study. It is not a paper, an official full-benchmark reproduction, or an admission to tune on these 80 pairs until a gain appears.
